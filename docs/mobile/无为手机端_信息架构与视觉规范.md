# 无为手机端 App · 信息架构 + 视觉规范

> 负责人：小移（移动端设计）｜版本：**v4（董事长逐屏审后 6 处修订）**｜技术栈：React Native / Expo，一套代码 iOS + 安卓
> 定位：**轻量版**——随身对话、查看任务进度、审批。重度本地工具操作留桌面端。
> 设计原则：**随身、快、清爽**。桌面端的复杂功能不硬塞进手机。
> 高保真原型：`docs/mobile/prototype/index.html`（浅色默认 · 375×812 · **35 屏全量**；逐屏 PNG 见 `docs/mobile/prototype/shots/`）
> 功能对齐文档：模型清单/倍率/执行位置/语音/审批均以真实实现为准，快照数据见 `docs/mobile/model-pricing-snapshot.json`

## 已拍板决策（v4）
1. **底部 Tab = 4 个**：对话 / 进度 / 审批 / 我。通讯录收进「我」（低频，发起新对话走对话 Tab 的「+」）。
2. **仅浅色白底**（董事长拍板：深色全砍，只做浅色；不提供主题切换）。
3. **游客先聊、需同步/审批才登录**：保留桌面端「免费·直接开聊」品牌一致性。游客态下点「审批 Tab / 任务同步」→ 引导登录态（不是空白页）。
   - **登录方式（v6 最终定稿）**：**账号密码为主**（账号框占位「账号 / 邮箱」，**不支持手机号登录**；输入区 + 主按钮在上，下带「注册账号 / 忘记密码」）；→「或使用以下方式」分割线 → 第三方**仅 2 枚：邮箱验证码 / Google**（微信、Apple 已去掉，Apple 不删代码位）。Google 用官方四色 G 标。**登录体系最终 = 账密（账号/邮箱）+ 邮箱验证码 + Google + 游客先聊；没有手机号 / 微信 / Apple。**
   - **验证码页（A3）= 邮箱验证码**：文案「邮箱验证码已发送至 x****x@xxx.com」，不是手机号。
4. **对话页三大核心**：① 消息流全类型打磨；② 对话内模型选择（输入框上方胶囊 → 点开 bottom sheet）；③ 订阅版顶部常驻余量条，按量付费不显示。
5. **模型选择 = 两级 bottom sheet**（对齐真实代码 `ModelSheet.tsx`）：一级选平台（provider 分组），二级选具体模型。**清单与倍率全由后端 `/api/model-pricing` 实时返回/计算**，前端不写死——免费=0，非免费里综合价（inCoins+outCoins）最低者=1× 基准，其余按比例。倍率 pill 染色：免费→绿 / ≥3×→朱赭 / 1~3×→靛青 / <1×→绿。
6. **执行位置选择器**：并进模型 sheet **顶部**（非独立页/设置页），**仅当有在线电脑时才显示**。选项=⚡无为托管（默认）+ 各在线电脑（带订阅类型/额度剩余），每台可「查看对话→」跳远程浏览页。
7. **语音输入 = 实时听写（v4 改）**：董事长拍板由"按住→松开→转写"两段式，改为 **实时语音输入**——录音时显示**实时声波动效** + 语音**边说边转文字上屏**（已确认文字黑、临时识别中文字灰 + 闪烁光标），**上滑取消**（滑到取消区变红、松手丢弃）。结束点 ✓ 把文字**填入输入框不直接发**，确认再发送。保留**失败兜底提示**（无权限/无网/没听清，2s 自动消失）。三屏：B6a 实时识别 / B6b 上滑取消激活态 / B6c 失败兜底。
8. **远程危险操作审批 = 独立审批 Tab**（对齐 `approval.tsx`，**非对话消息流内弹卡**）：工具名 + 💻设备名 + 参数预览（monospace，≤3 行）；**60 秒不处理自动拒绝**；按钮只有「拒绝 / 允许」；底部 Tab 红点 20s 轮询。**接入 RiskBadge 风险徽章**（高红/中金/低靛青——组件已存在但真实代码尚未接入，设计先给到位，推动小码接）。
9. **远程设备浏览页** `/remote/[deviceId]`：从执行位置「查看对话→」进入；顶部 4 Tab（对话/员工/群聊/SOP），经 relay 实时读该电脑本地内容、分页、**不落库**。无独立「设备档案页」，设备字段在选择器行内回显。
   - **4 个二级详情页**：列表项点进去都有详情页。**注意区分"可续聊"与"只读"——会话续聊是手机端灵魂功能（远程操控电脑端 agent），必须能用；其余为只读**：
     - **G1a 会话详情（可续聊 · v5 重大修正）**：手机端核心 = **远程操控电脑端的无为**。顶部常驻「正在远程操控 MacBook-Pro（我的）」状态条；底部是**可用的输入框+发送**（不是灰字禁用）；手机发消息 → 经 relay 同步到该电脑 → 电脑端 agent 执行 → 结果回流手机显示，**双向同步**（电脑端也同步看到手机发的文字）。轻提示「消息将发送到该电脑执行、电脑端可同步查看」。*真实 relay 链路（relay.wuweiai.io:8792 A 路线 / 设备 id 复用 ~/.wuwei/device-id 的 wd_ 前缀）属 M2 架构活，原型按此合理占位、标注待与小码对齐。*
     - G2a 员工详情：该 AI 员工人设/职责/当前状态（**只读**，编辑人设去桌面端）
     - G3a 群聊详情：该群聊消息记录（**只读**，不可发言）
     - G4a SOP 全文：正文阅读页（**只读**，底部注「编辑/新建请到桌面端 SOP 库」）
10. **余额卡 = 无为币只读（v4 改）**：那个数字是**无为币**不是人民币——去掉 ¥/元含义。显示 = **无为币图标 + 大数字「328」+ 下方标签「无为币余额」**（带「仅展示」角标）。**去掉充值 / 明细按钮**，本阶段纯只读数字展示。合规延续：不做任何 App 内支付入口，充值引导只做灰底文案指向电脑端/官网。
11. **定时任务入口（v5 已拍 = 方案A）**：进度页右上角时钟图标 + 「定时」文字标签（原裸图标太隐蔽，加文字标签后可识别）。方案B（顶部入口条）已弃用、原型中删除。
12. **登录流程补齐 4 页（v6 新增）**：
    - **A5 注册账号**：只走邮箱——邮箱 + 邮箱验证码（获取验证码按钮）+ 设置密码（8-20 位）+ 协议勾选（默认勾，含可点《用户协议》《隐私政策》链接）+「注册并登录」+「已有账号？去登录」。不支持手机号。
    - **A6 忘记密码**：注册邮箱 + 邮箱验证码 + 设置新密码 + 确认新密码 +「确认重置」+「返回登录」。
    - **A7 用户协议 / A8 隐私政策**：独立全屏可滚动阅读页（返回 + 标题 + 正文）。正文为占位标准框架（协议：服务说明/账号与注册/用户行为规范/知识产权/免责声明/协议变更/联系方式；隐私：信息收集范围/使用方式/存储与安全/第三方共享/用户权利/Cookie 与设备/政策更新/联系我们），注明"法务细则以正式版本为准"。
    - **协议链接可点**：登录页 A2 底部与注册页 A5 的《用户协议》《隐私政策》均为 accent 色 + 下划线的可点链接（`.agree-link`），分别跳 A7 / A8。

## 二、信息架构 / 导航结构

### 底部 Tab（已定 = 4 个）
**4 个主 Tab**（通讯录收进「我」，避免 Tab 过多）：

```
┌─────────────────────────────────────────┐
│  💬 对话   │  📊 进度   │  ✅ 审批●  │  👤 我  │
└─────────────────────────────────────────┘
   Tab1        Tab2        Tab3(红点)   Tab4
```

> 审批 Tab 带未读红点（对应桌面 `acct-unread` 那颗 #E5484D 红点逻辑），是手机端最高价值的"随身拍板"场景，给它独立 Tab。

### 页面跳转关系（文字流程图）

```
Splash(A1)
  └─ 已登录? ── 是 ──► 主框架(底部Tab)
                └─ 否 ──► 登录(A2) ──► 验证(A3) ──►（首次)引导(A4)──► 主框架
                          └─ [游客直接开聊] ──► 对话详情(B2)

主框架
├─ Tab1 对话
│   └─ 会话列表(B1)
│        ├─ 点会话 ──► 对话详情(B2)
│        │              ├─ 点工具行 ──► 工具详情抽屉(B3)
│        │              └─ 顶部任务标 ──► 任务详情(C2)
│        ├─ [+新建] ──► 新建对话(B4) ──► B2
│        └─ [搜索] ──► 会话搜索(B5) ──► B2
│
├─ Tab2 进度
│   └─ 任务进度(C1)
│        ├─ 点任务 ──► 任务详情(C2) ──► 关联会话 B2
│        └─ [定时] ──► 定时任务(C3)
│
├─ Tab3 审批 ●
│   └─ 审批中心(D1)
│        └─ 点条目 ──► 审批详情(D2)
│                       ├─ 通过/拒绝 ──► 回 D1（红点-1）
│                       └─ 查看会话 ──► B2
│
└─ Tab4 我
    └─ 我(F1)
         ├─ 通讯录(E1) ──► 员工详情(E2) ──► 发起对话 B2
         ├─ 账号与安全(F2)
         ├─ 通用设置(F3)  [外观(仅浅色)/语言/通知]
         └─ 关于/帮助(F4)
```

### 三条黄金动线（手机端最该顺滑的路径）
1. **随时接着聊**：打开 App → Tab1 → 点会话 → 继续对话。（≤2 步）
2. **盯任务**：收到进度通知 → 点开 → 任务详情看到哪一步了。（≤2 步）
3. **快速审批**：推送「有操作待审批」→ 点开 → 看清动作 → 通过/拒绝。（≤2 步，可从通知直达 D2）

## 三、视觉规范草稿（从桌面端 theme.css 提炼）

### 品牌内核
- Slogan：**「一念既出，万事自成」**
- 三步流：**发念 → 有为 → 成事**
- 主标：一念之门「圆相火种」——圆环描边 + 中心朱赭点（呼吸动画）。手机端 App 图标 / 启动页 / 空状态复用。
- 气质：白底 + 墨字 + 靛青导航 + 朱赭一念火种（朱赭≤10%，只给主操作）。品牌基因沿用桌面「玄墨/月白/靛青/朱赭」的色相，手机端落为浅色版。

### 配色（**仅浅色白底**，深色已砍）
| 用途 | 变量 | 色值 |
|---|---|---|
| 主背景 | bg | `#FFFFFF` |
| 次背景 | bg-soft | `#F4F6F8` |
| 卡片/浮层 | bg-raised | `#EEF1F4` |
| 分隔线 | border | `#E0E4E8` |
| 分隔线（强） | border-strong | `#CFD5DB` |
| 主文字 | text | `#16191E` |
| 次文字 | text-dim | `#5B656D` |
| 辅助/弱文字 | text-muted / faint | `#5B656D` / `#8A929A` |
| **导航/选中/链接（靛青）** | accent | `#274A63` |
| **主操作/一念火种（朱赭）** | spark | `#C05F3C` |
| 成功/连通（竹青） | green | `#3F8F6B` |
| 错误 | red | `#E5484D` |
| 警告/暖金 | warn / gold | `#C8933F` / `#C9A24B` |
| 红点/未读 | — | `#E5484D` |
| 代码块底 | code-bg | `#F4F6F8`（浅灰，语法高亮=靛青+竹青） |

> **仅浅色白底**（董事长拍板深色全砍：干净清爽、留白足）。设置页「外观」只展示浅色、不提供主题切换。
> 浅色下的三处特殊处理：① 代码/命令块用浅灰底而非黑底；② 进度条槽用分隔线灰（比背景深才看得出填充）；③ 呼吸点/spinner 描边改灰，浅底不糊。

### 字体
- 中文：苹方(iOS 自带) / 思源黑体兜底；英文数字：Inter / SF Pro。
- 等宽（代码/命令/数字）：SF Mono / JetBrains Mono。
- 移动端字号建议（比桌面放大保证触屏可读）：
  - 大标题 20 / 标题 17 / 正文 15 / 次要 13 / 辅助 12。
  - 行高 1.5–1.7。

### 关键组件风格（对齐桌面）
| 组件 | 规范 |
|---|---|
| **圆角** | 卡片 12–14、气泡 13、按钮/胶囊 999、输入框 10 |

## 三·补、合规与边界约定（吸收自小美一页纸，手机端红线）

> 凡涉及「钱 / 重操作 / 数据写入」的页面，按本节收口。两条红线：

### 红线① 苹果 IAP —— 余额只展示、不做支付入口
- 「我」页**余额卡 = 只读卡**：中性深灰底、带「**仅展示**」角标，**不放任何充值/支付/购买按钮**。
- 引导充值只用**灰底浅字文案**「如需充值，请前往电脑端或官网操作。移动端仅供查看余额。」——是文案，不是可点支付入口/外链直跳。
- 视觉上**不能长得像可点的支付按钮**（不用高饱和主色大按钮 / 不用"立即充值"CTA 诱导点击）。
- 订阅（Pro）卡同理：**不做 App 内续费入口**，续费引导去电脑端/官网，卡内 CTA 改「查看权益」。
- 数据字段：余额读 `coin.balance`（**不是**顶层 `balance`，后者永远空）。
- **自查**：把余额卡给第三人看，问"这像能点的支付按钮吗？"——答"是"即不合格。

### 红线② 能力边界 —— 本地重活当场挡回、引导去电脑端
- 对话详情内置「**边界提示条**」：用户让助手干手机端做不了的本地重活（跑重任务 / 动本地文件、环境 / 大数据导出等）时，出一条 **info 中性层级**提示（区别于危险红、区别于普通气泡）。
- 文案口径：**说清去哪、为什么**（如"该操作涉及读写本地文件与重算力，请到电脑端无为完成，结果可随时在手机查看"），不说"我不能"就完事。
- 样式见原型 `.boundary-note`（靛青 info 条）；示例在 B2a 对话详情运行中。

### 其它只读/边界约定
- **定时任务**：手机端查看 + 开关，**创建/编辑留桌面**（页头「桌面创建」+ 页内注明）。
- **SOP 库**：手机端只读查看，**编辑/新建在桌面端**（页脚注明）。
- **进度/会话/群聊**：只读查看云端 + 本地内容，本地数据标注「存本地·加密实时读·不落库/不上传」。
- **审批**：可在手机确认，但权限动作往返回云端校验。

### 收口 checklist（每次发版前过一遍）
- [x] 「我」页余额卡：深灰 + 「仅展示」角标 + 灰底引导文案 + **无任何支付按钮**
- [x] 余额字段读 `coin.balance`
- [x] 对话详情有「边界提示条」样式，文案引导去电脑端
- [x] 定时任务 / SOP 标注"创建/编辑在桌面端"
- [x] **全端搜「充值 / 立即购买 / 支付 / 付款」字样或按钮样式 → 已清零**（唯一保留的"充值"二字在引导文案内，非按钮）
